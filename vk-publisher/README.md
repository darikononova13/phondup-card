# PHONDÜP — публикации во ВКонтакте

Это отдельный модуль в уже подключённом репозитории электронной визитки. Файлы визитки в папке public/ не менялись. Группа: https://vk.ru/phondup. Публичный ID сообщества: `162848624`. Номер задан в `.github/workflows/vk-publish.yml` и не является секретом.

## Безопасное подключение ключа (один раз)

1. Откройте https://github.com/darikononova13/phondup-card/settings/secrets/actions
2. Нажмите **New repository secret**.
3. В поле **Name** введите `VK_ACCESS_TOKEN`.
4. В поле **Secret** вставьте созданный в настройках VK API токен и сохраните кнопкой **Add secret**.
5. Откройте вкладку **Actions** в репозитории, выберите **PHONDUP VK — publish approved posts**, нажмите **Run workflow**. Это проверка прав токена сообщества через `groups.getTokenPermissions` — публикация не выполняется.

⚠️ Никогда не помещайте ключ в чат, GitHub-файлы, скриншоты или сообщения клиентам. Если ключ случайно раскрыт, отзовите его и создайте новый. Ключ сообщества может оказаться недостаточным для wall.post; в таком случае понадобится другой тип авторизации, а не передача дополнительных секретов в чат.

## Как позже публиковать

После вашего подтверждения окончательного текста создаётся **новый** файл в `vk-publisher/outbox/` с уникальным именем, например `2026-10-27-phondup-display.json`:

```json
{
  "approved": true,
  "message": "Пример текста публикации. Не отправлять без подтверждения.",
  "attachments": []
}
```

Публичный числовой ID сообщества `162848624` уже внесён в GitHub Actions как `VK_GROUP_ID`; дополнительно сохранять его в Secrets and variables не требуется.

Только **новый** файл в папке outbox, добавленный в ветку main, запускает публикацию. `approved` должно быть `true`. `attachments` — массив уже загруженных в VK идентификаторов `photo-12345_67890` или `video-12345_67890`.

Готовые фотографии и видео пока нужно загружать в VK отдельно: автоматическая загрузка новых файлов ещё не подключена и может требовать другого типа токена. Для текстов и уже загруженных вложений предусмотрен маршрут публикации.

Результат и ссылку на опубликованный пост можно увидеть во вкладке **Actions** в журнале соответствующего запуска. Секрет в журнал не выводится.

## Ограничения

- Проверка прав ключа не доказывает успешность метода `wall.post`. Первую публикацию делайте только после проверки разрешений и утверждения текста.
- В этом модуле нет планировщика публикаций или чтения комментариев; это следующие этапы.
- GitHub Actions не являются прямым интеграционным коннектором к интерфейсу ChatGPT. После вашего одобрения можно создавать файл в GitHub с помощью подключённого инструмента.
- Для экономии и защиты данных не добавляйте клиентские персональные сведения в публичный репозиторий.

## Фото вместе с постом (этап подготовки, пока НЕ подключен полностью)

Сообщество PHONDÜP: ID `162848624`.

**Важно:** токен сообщества из `VK_ACCESS_TOKEN` успешно прошёл проверку, но сам по себе не может выполнить `photos.getWallUploadServer` (VK отвечает 27). Для загрузки фото нужен **отдельный OAuth user-token администратора** с разрешениями на фотографии. Создавайте его только через официальный авторизационный интерфейс вашего приложения VK; не сообщайте пароль, коды SMS, cookie и токены в чате.

Храните этот пользовательский токен как отдельный секрет GitHub Actions `VK_USER_TOKEN` (НЕ заменяя ключ сообщества).

Новый модуль `vk-publisher/upload_photos.py` автоматически:
1. Получает адрес загрузки (`photos.getWallUploadServer`) с пользовательским токеном администратора.
2. Загружает JPG/PNG с локального пути из `vk-publisher/media/` (до 10 МБ).
3. Сохраняет фото на стену через `photos.saveWallPhoto`.
4. Возвращает ID фото. Основная программа добавляет его в `attachments` при `wall.post` от имени сообщества.

Формат утверждённого файла:

```json
{
  "approved": true,
  "message": "Утверждённый текст публикации",
  "attachments": [],
  "images": ["vk-publisher/media/example.jpg"]
}
```

**Пока нужны ещё два действия перед реальной публикацией с фотографией:** передавать секрет `VK_USER_TOKEN` в шаг публикации GitHub Actions и помещать одобренную картинку в media/ (или организовать её автоматический перенос туда). Оба шага не завершены. Не добавляйте посты с `images` в outbox до этого. Программа проверяет явное `approved: true` и не публикует черновики из drafts/.
